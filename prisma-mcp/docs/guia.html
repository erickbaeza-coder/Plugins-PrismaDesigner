Instalación

3 pasos · 5 minutos
A. Clonar o copiar la carpeta del MCP en tu máquina
El MCP es una carpeta con código Node.js. Necesitás tenerla en tu computadora para que funcione.
Terminal
git clone [URL_DEL_REPO] prisma-mcp
cd prisma-mcp
npm install
Pedile al lead de diseño la URL del repositorio privado del equipo.
Copiá la carpeta Prisma MCP a tu máquina (Desktop, Documentos, o donde prefieras). Después: 
cd "[ruta donde copiaste la carpeta]/Prisma MCP"
npm install
Ejemplo: cd ~/Desktop/Prisma MCP && npm install
✓ Solo necesita instalarse una vez. Después no es necesario correrlo de nuevo.
B. Obtener tu Figma Personal Access Token
El MCP necesita este token para leer tu librería de Prisma-Components.
Abrí Figma en el browser
figma.com → tu foto de perfil (arriba a la izquierda)
Settings → Security
En el menú de tu cuenta, ir a Settings y luego a la tab Security
Personal access tokens → Generate new token
Nombralo "Prisma MCP" y copiá el token que genera (empieza con figd_)
Guardalo en un lugar seguro
Solo se muestra una vez — si lo perdés tenés que generar uno nuevo
⚠️ No compartas este token ni lo commiteés a Git. Tiene acceso de escritura a tus archivos de Figma.
C. Registrar el MCP en Claude Cowork
Abrí (o creá) el archivo ~/.claude/mcp_settings.json y agregá esta config.
Reemplazá los dos valores marcados con tu información real.
~/.claude/mcp_settings.json
{
  "mcpServers": {
    "prisma-mcp": {
      "command": "node",
      "args": [
        "/ruta/a/tu/carpeta/Prisma MCP/src/index.js"
      ],
      "env": {
        "FIGMA_TOKEN": "figd_TU_TOKEN_AQUI"
      }
    }
  }
}
¿Cómo sé cuál es mi ruta?
Abrí Terminal y corré este comando — te imprime la ruta exacta donde está el archivo:
find ~ -name "index.js" -path "*/Prisma MCP/*" 2>/dev/null
Copiá esa ruta y pegala en el campo args del JSON de arriba.
Reemplazá figd_TU_TOKEN_AQUI con el token que generaste en el paso B.
Si ya tenés otros MCPs configurados, agregá prisma-mcp dentro del objeto mcpServers existente — no reemplaces todo el archivo.
Después de guardar: reiniciá Cowork para que cargue el nuevo MCP.
D. Verificar que el FIGMA_TOKEN está activo
Podés verificar si ya tenés el token configurado antes de editarlo. Abrí Terminal: 
echo $FIGMA_TOKEN
Si devuelve vacío, el token no está. Agregalo en ~/.zshrc:
echo 'export FIGMA_TOKEN="figd_TU_TOKEN_AQUI"' >> ~/.zshrc
source ~/.zshrc
✓ También podés poner el token directamente en el mcp_settings.json — funciona igual.

Composiciones — componentes que no existen en Prisma

Cómo el MCP maneja los componentes nuevos
Cuando el DS3 define un componente que no existe en Prisma-Components (ej: EventCard), el MCP no lo deja como placeholder. En cambio genera dos outputs:
① Composición DS3
Sub-árbol de componentes Prisma existentes que aproximan el componente nuevo. Se incluye en el script de use_figma como frame anidado.
② Auto-creado en Figma
El script generado incluye las composiciones y las crea directamente en el canvas. No hace falta Figma Make ni intervención manual.
Composiciones frecuentes (del caso TFM Events)
ComponenteSub-componentes PrismaCuándo aparece
EventCard Banners terciarios Md + Tag + Title_section Feed cronológico de eventos
EventMetadata Location Brand × 3 (fecha, hora, lugar) Detalle de evento
GateContent Tag Green + Title_section + InformationCard Brand + Button Primary + Button Secondary Gate de membresía
EventCardMO Banners terciarios Md + Tag Green + Title_section Card evento bloqueado (anonymous)
SkeletonCard Banner principal Sm + Title_section Estado loading del feed
Workflow recomendado: ejecutá use_figma con el script completo → los frames aparecen en la nueva página con brand mode aplicado → si hay composiciones, revisá el frame y ajustá a mano si hace falta.

Herramientas disponibles

9 tools que podés usar desde Claude
sync_prisma_library
Escanea el archivo Prisma-Components en Figma y enriquece el catálogo con los component keys reales.
Usar: una vez antes de empezar o cuando se actualiza la librería
create_screens_from_ds3
Toma el packets.ds3 JSON y genera la spec enriquecida, resuelve componentes, detecta los nuevos y produce warnings.
Usar: después de ejecutar el paso DS3 del proceso agéntico
create_screens_from_prompts
Convierte prompts de texto en componentes Prisma inferidos automáticamente y genera el JSON para Prisma Builder.
Usar: cuando tenés los prompts del output_ds3.md pero no el JSON
validate_ds3_json
Valida el JSON contra el catálogo Prisma y reporta errores (grupos inválidos, props inexistentes, componentes no encontrados).
Usar: antes de ejecutar create_screens para detectar problemas
list_prisma_components
Lista todos los componentes disponibles en el catálogo, con filtro opcional por nombre o grupo.
Usar: cuando querés saber qué existe antes de diseñar
resolve_component
Encuentra el componente Prisma que mejor coincide con una descripción en lenguaje natural. Evita errores comunes.
Usar: cuando no recordás el nombre exacto de un componente
create_local_component_spec
Genera la composición DS3 y el prompt de Figma Make para un componente nuevo que no existe en Prisma.
Usar: cuando necesitás un componente que aún no está en la librería
get_figma_file_info
Obtiene info de un archivo Figma: nombre, páginas disponibles, componentes locales, fecha de modificación.
Usar: para verificar que el archivo destino es el correcto
generate_figma_script
Genera el script JavaScript completo (use_figma) desde un DS3 JSON. Crea la página, coloca los frames con los componentes Prisma resueltos y aplica el brand mode automáticamente.
⭐ Nuevo en v2.0 — es el paso final del flujo DS3 → Figma directo

Errores comunes y soluciones

Problemas frecuentes y cómo resolverlos
Causa más común: Claude no se reinició después de editar mcp_settings.json.

Solución: Cerrá y volvé a abrir Cowork / Claude Code completamente (no solo la ventana). Si seguís sin verlo, verificá que el JSON de la config es válido (no tiene comas extra ni comillas incorrectas).
El token no está pasando bien a la variable de entorno del MCP.

Verificar: en mcp_settings.json asegurate de que la key sea exactamente FIGMA_TOKEN y que el valor sea tu token completo (incluyendo el prefijo figd_).
El token de Figma expiró o no tiene los permisos correctos.

Solución: Generá un nuevo token en Figma → Settings → Security → Personal access tokens. Actualizá el valor en mcp_settings.json y reiniciá Cowork.
El MCP tiene un catálogo base de los componentes documentados en el DS3 skill. Si usás componentes que no están en ese catálogo, aparecen como "no encontrados".

Solución: Ejecutá sync_prisma_library con la URL del archivo Prisma-Components real de tu team. Eso actualiza el catálogo con los componentes reales y sus keys de Figma.
El DS3 JSON tiene componentes con prefijos de diseño atómico (Atoms >, Molecules >, Organisms >) que no existen en Figma.

Solución: Pedile a Claude que corrija el JSON usando resolve_component para cada componente problemático. El MCP sugiere el nombre correcto en Prisma.
Esto ocurría en versiones anteriores del script generado, donde figma.currentPage = page no funcionaba (la asignación directa no está soportada por la Figma Plugin API).

En v2.0 está corregido: el script usa await figma.setCurrentPageAsync(page) antes de crear los frames. Si ves este problema, asegurate de que el MCP está en v2.0 o superior (reiniciá desde Settings → Developer → MCP → prisma-mcp → Restart).
Puede pasar si el DS3 JSON no tiene el campo marca o si el nombre no coincide exactamente con el nombre del modo en Figma.

Verificar: en el DS3 JSON, el campo marca debe ser exactamente igual al nombre del mode en la colección "2-Style Tokens" de Figma (ej: "The Fresh Market", no "TFM"). Si no coincide, el script aplica sin brand mode pero sin romper la creación de frames.

Compartir con el equipo

Tres opciones según el nivel de infraestructura que quieran invertir
Opción 1 · Recomendada Repositorio Git privado
Subís la carpeta Prisma MCP a un repo privado de GitHub/GitLab. Cada diseñador clona el repo, corre npm install y configura su propio FIGMA_TOKEN.
VentajaLimitación
Cada uno tiene el MCP en su máquina · Updates con git pull · Sin infraestructura extra Cada designer tiene que clonar y correr npm install · Si alguien no tiene Node, necesita instalarlo 
# Cada designer hace esto una sola vez:
git clone https://github.com/tu-org/prisma-mcp.git
cd prisma-mcp
npm install

# Para recibir actualizaciones:
git pull
Opción 2 Paquete npm privado
Publicás el MCP como paquete en el registry privado de npm (o GitHub Packages). Cada designer instala con un solo comando global.
VentajaLimitación
Instalación con un comando · Versiones controladas · No hay que clonar repos Requiere publicar en npm/GitHub Packages · Necesita acceso al registry privado 
# Instalación (cada designer, una vez):
npm install -g @cencosud-ux/prisma-mcp

# Config en mcp_settings.json — sin path, solo el comando:
{
  "mcpServers": {
    "prisma-mcp": {
      "command": "prisma-mcp",
      "env": { "FIGMA_TOKEN": "figd_TU_TOKEN_AQUI" }
    }
  }
}
Opción 3 · Avanzada Servidor compartido (hosted MCP)
Deployás el MCP en un servidor (Railway, Render, Fly.io) con transporte SSE. Todos los designers se conectan a la misma URL — sin instalar nada localmente.
VentajaLimitación
Un solo servidor para todo el equipo · Updates instantáneos · Sin instalación en cada máquina Requiere infraestructura y mantenimiento · El catálogo Prisma es compartido (no por designer) 
# Config en mcp_settings.json — solo una URL:
{
  "mcpServers": {
    "prisma-mcp": {
      "url": "https://prisma-mcp.tu-dominio.com/sse",
      "headers": {
        "Authorization": "Bearer ${FIGMA_TOKEN}"
      }
    }
  }
}
Esta opción requiere cambiar el transporte de StdioServerTransport a SSEServerTransport en el código del servidor. No es compatible con la configuración actual sin modificar src/index.js.
Para el equipo hoy: la Opción 1 (Git repo) es la más simple y no requiere infraestructura. Cuando el equipo crezca o quieran centralizar actualizaciones, la Opción 3 es el paso natural siguiente.
